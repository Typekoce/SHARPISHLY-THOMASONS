## 🔍 CURRENT FRICTION
* **The "Payload" Wall:** The Neural Worker was stuck in an infinite loop on Job #1. Every time it tried to update the status, MySQL threw `Error 1364: Field 'payload' doesn't have a default value`. 🛑
* **Service Decoupling:** The `Db` service was lacking access to the `Logger`, leading to bootstrap crashes when trying to report migration errors.
* **Schema Evolution:** Needed a way to track database changes (ADD/MODIFY/DROP) without resorting to untraceable raw SQL.

## 📝 SCRATCHPAD
* **The Fix:** Changed `payload` column to `TEXT NULL DEFAULT NULL`. This allows the `UPSERT` logic to bypass the `INSERT` requirements for missing data during a status update. 🏗️
* **Dependency Injection:** Updated `BaseController` to instantiate `Logger` first, then inject it into the `Db` service constructor. 💉
* **FIFO Order:** Switched `JobController::index` to `ORDER BY id ASC` to ensure the oldest jobs are processed first (FIFO) rather than the newest (LIFO). 🏎️

## ✅ LESSONS LEARNED
* **Strict Mode Nuance:** In MySQL `Strict Mode`, an `INSERT ... ON DUPLICATE KEY UPDATE` still validates the `INSERT` constraints (like `NOT NULL`) even if the row already exists and only the `UPDATE` part is needed. **Always make metadata columns nullable if they aren't part of every request.** 🛡️
* **Logger Availability:** Services that perform critical operations (like `Db`) must have the `Logger` injected immediately to prevent "silent" crashes or bootstrap errors during schema migrations. 🪵
* **Automation over Manual SQL:** Using a structured `$db->alter()` method makes schema changes idempotent and traceable in the application logs, rather than being "lost" in the terminal history. ✅
